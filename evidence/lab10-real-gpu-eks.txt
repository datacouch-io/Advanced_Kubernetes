=== Real GPU node autoscaling from zero: live tested on AWS EKS ===

eksctl-created managed node group 'gpu-ng': g4dn.xlarge, AmazonLinux2023 (accelerated AMI),
desiredCapacity=0 minSize=0 maxSize=1, tainted nvidia.com/gpu=true:NoSchedule.
eksctl auto-installed the NVIDIA device plugin because it detected the accelerated AMI + GPU
instance type -- no manual device-plugin manifest needed.

Cluster Autoscaler 1.35.0 (chart default) got stuck in a permanent retry loop trying to watch
DRA-related API types (DeviceClass, ResourceClaim, ResourceSlice) that don't exist on this
EKS 1.33 cluster -- 'the server could not find the requested resource', repeating forever and
never reaching the actual scale-up evaluation loop. Pinning image.tag=v1.33.0 (matching the
cluster's Kubernetes minor version, instead of the chart's newer default) resolved it immediately.

IAM gotcha: the autoscaling IAM policy must be attached to the role of the node group the
Cluster Autoscaler POD actually runs on (here: cpu-ng, the only node group with a running node
at the time) -- NOT the target GPU node group's role, which has no running instances yet to
even host the CA pod. Attaching it to gpu-ng's role first produced:
  AccessDenied: ... assumed-role/eksctl-...-nodegroup-c-... is not authorized to perform:
  autoscaling:DescribeAutoScalingGroups
